1 Project Genesis: How It Started

Core Vision & Cultural Identity Vision

Build Tabraiz, a conversational voice AI tailored for Pakistan. It had to speak natural, polite Pakistani Urdu (not machine-translated English), observe strict societal respect (addressing users with 'آپ' and strictly forbidding 'تم/تو'), and speak concisely (2 to 3 sentences) for fluid audio playback.

Strict Technical & Cost Boundaries Zero Cost Policy

Zero Local GPU Load: The user's local PC must remain cool and silent (0% local GPU/CPU load).
Zero GCS Bucket Costs: Storing weights on Google Cloud Storage incurs recurring fees; eliminated completely.
Dual-Voice System: Male persona Tabraiz (ur-PK-AsadNeural) & female Tehzeeb (ur-PK-UzmaNeural).

4 LoRA Fine-Tuning: Curriculum, Data Sourcing & Training

1. Data Sourcing: Pakistan Curriculum Engine Dataset

Raw internet datasets lack proper etiquette and accurate Pakistani facts. We built pakistan_curriculum_engine.py containing 200 curated topics across 8 distinct Pakistani categories:

  • Culinary Heritage: Sindhi Biryani, Nihari variations, Balochi Sajji, Chapli Kabab, Haleem.
  • National History: 1940 Resolution, 1947 partition, Quaid-e-Azam, Allama Iqbal, 1973 Constitution.
  • Languages & Dialects: Urdu, Punjabi Sufi poetry, 52-letter Sindhi script, Pashto, Balochi, Seraiki.
  • Geography & Economy: Indus river irrigation, K2, Gwadar port, Thar coal, Karakoram Highway.
  • Institutions & Sports: NADRA, FBR, PTA, Cricket World Cup, PSL, Arshad Nadeem.
2. ChatML Synthesis & PEFT/LoRA Pipeline Training

Data was formatted into authentic ChatML conversations and trained directly on Modal.com Serverless GPU (NVIDIA L4) via deploy_adaab.py:

Base Model: Qwen/Qwen2.5-7B-Instruct
Quantization: 4-Bit BitsAndBytes (QLoRA)
LoRA Rank (r): 16 | LoRA Alpha: 32 | Dropout: 0.05
Target Modules: q_proj, k_proj, v_proj, o_proj, gate, up, down
Loss Function: CrossEntropy on Assistant Tokens Only
Adapter Size: ~52 MB (Portable, cached on Modal Volume)

Why LoRA? Allowed teaching Tabraiz respectful Pakistani Urdu and deep cultural facts without the massive compute cost of full 7B parameter retraining.

5 RAG Grounding: Why It's Challenging & How It Was Solved

Challenge 1: Script & Bidi Conflict

Urdu is strictly Right-to-Left (RTL), but web search URLs, citations, and numbers are Left-to-Right (LTR). Injecting raw search results caused reversed brackets and syntax errors in TTS audio.

Solution: Isolated citations, clean unicode normalization, and plaintext speech generation.

Challenge 2: Verbal Verbosity

LLMs reading web search snippets default to reciting long 400-word encyclopedic essays. For a voice assistant, long paragraphs result in boring, robotic speech.

Solution: Pre-Standard Directive enforcing Voice Brevity (strictly 2–3 sentences of summarized truth).

Challenge 3: Paid Search API Costs

Google Custom Search API and Bing Search API require credit card registration, billing accounts, and cost $5–$15 per 1,000 queries.

Solution: Built an authentic DuckDuckGo HTML scraper with zero API keys and 100% zero-cost search.

Records conversational exchanges to feed context back into future turns.

3. active_topics Table
session_id TEXT PRIMARY KEY
active_topic TEXT
last_query TEXT
turn_count INTEGER
updated_at TIMESTAMP

Tracks the active subject to resolve anaphora / follow-up queries ('aur?').

Asynchronous Silent Persistence Policy Zero Voice Latency

All SQL operations execute in a detached ThreadPoolExecutor(max_workers=2) named adaab_silent_mem. When a user mentions their name (e.g. 'Mera naam Ali hai'), the database extracts and updates SQLite in the background. The system never announces database writes to the user and never delays audio generation by a single millisecond.

12 Enterprise Security Architecture & Data Guardrails

1. Automated PII Redaction

Real-time regex & NER pipeline scrubs 13-digit Pakistani CNICs (\d{5}-\d{7}-\d), mobile numbers (03\d{2}-\d{7}), and street addresses before query text touches any external cloud API or log file.

2. OWASP LLM Defense

Guards against Prompt Injection (LLM01) and Sensitive Disclosure (LLM06). Sanitizes malicious inputs attempting to bypass the persona or extract internal database paths.

3. Data Sovereignty & Encryption

Full TLS 1.3 encryption in transit. SQLite databases encrypted with SQLCipher (AES-256). For state clients (NADRA/SBP), supports air-gapped on-premise deployments.
