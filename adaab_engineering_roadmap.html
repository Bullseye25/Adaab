3 Key Challenges Encountered & Major Engineering Time Sinks

Real Engineering Challenge Root Cause Diagnosed Exact Solution Applied & Engineering Investment
1. Urdu ASR Code-Switching & Transliteration Trap
TIME SINK: 5 DAYS		 Google Speech API in Urdu (ur-PK) phonetically transcribed English speech into Arabic script (e.g. 'ہائی تبریز کین یو سوئچ ٹو انگلش') rather than English text, corrupting chat bubbles and causing intent misfires. Dynamic Dual-Probe ASR Architecture: Engineered acoustic detection in voice_listener.py. When phonetic transliteration is detected, it probes Google en-US to recover pure English, backed by a transliteration normalizer.
2. Urdu Pronunciation, Acronyms & Diacritics in TTS
TIME SINK: 4 DAYS		 Neural voices (ur-PK-AsadNeural) mispronounced English loanwords, acronyms (CEO read as currency, SIM, CNIC, DLIMS, PTCL), and homographs lacking zer-zabar-pesh diacritics. Phonetic Preprocessing Engine: Built voice_reader.py phonetic dictionary mapping technical acronyms to spoken Urdu (سی ای او, نادرا), converting numerals into Urdu words, and enforcing polite آپ cadence.
3. Urdu LLM Incoherence & Repetition Loops
TIME SINK: 6 DAYS		 Raw Qwen 2.5 7B suffered from severe tokenization fragmentation for Urdu script (2–4 tokens/char) and pretraining bias, causing catastrophic repetition loops (repeating identical clauses 3–4 times) and trailing numbers. Modal A100 QLoRA + Anti-Looping: Curated 1,125+ ChatML turns, fine-tuned all 7 projection matrices, tuned repetition_penalty=1.25, no_repeat_ngram_size=4, and built a 5-gram loop pruning filter.
4. Cognitive Orchestration of Compound Voice Queries
TIME SINK: 3 DAYS		 Users speak compound instructions (e.g. 'Can you switch to English and tell me about Jazz'). Default architectures only acknowledge the switch and completely drop the user's actual question. Contextual Query Extraction: Built extract_substantive_query_after_switch() in orchestrator.py, enabling immediate language switching while answering the substantive question in English.
5. Mobile Safari Web Audio & iOS Screen Recording Muting
TIME SINK: 3 DAYS		 iOS Safari blocked unprompted audio autoplay, squished headers on compact screens (iPhone SE 2020), and muted user microphone during native iOS screen recording due to default VoiceProcessingIO. Mobile Audio & Viewport Hardening: Switched iOS audio units to RemoteIO with noise suppression, implemented strict 100dvh flexbox layout locks, and automated mic permission prompting on first user interaction.
6. Zero-Cost Sovereign Cloud Infrastructure & Storage
TIME SINK: 2 DAYS		 Cloud GCS buckets incur recurring storage and egress bills, and local consumer hardware was insufficient for heavy Qwen fine-tuning. Modal Serverless + Google Drive v3: Migrated training to burst Modal NVIDIA A100 ($2.79/hr), serving to L4 ($0.80/hr with scale-to-zero), and weights backup to Google Drive v3 API (5TB free personal quota).

5 RAG Grounding: Why It's Challenging & How It Was Solved

Challenge 1: Script & Bidi Conflict

Urdu is strictly Right-to-Left (RTL), but web search URLs, citations, and numbers are Left-to-Right (LTR). Injecting raw search results caused reversed brackets and syntax errors in TTS audio.

Solution: Isolated citations, clean unicode normalization, and plaintext speech generation.

Challenge 2: Verbal Verbosity

LLMs reading web search snippets default to reciting long 400-word encyclopedic essays. For a voice assistant, long paragraphs result in boring, robotic speech.

Solution: Pre-Standard Directive enforcing Voice Brevity (strictly 2–3 sentences of summarized truth).

Challenge 3: Paid Search API Costs

Google Custom Search API and Bing Search API require credit card registration, billing accounts, and cost $5–$15 per 1,000 queries.

Solution: Built an authentic DuckDuckGo HTML scraper with zero API keys and 100% zero-cost search.
